# 備品管理

社員に支給する PC・マウス・キーボード・モニター・セキュリティカード・社用携帯などを、
**「誰が何を持っているか」**で管理する台帳アプリです。支給・交換・返却・回収を記録し、
社員ごとの手持ちと履歴をいつでも確認できます。

- **ホームから日々の作業へ** — 物品の登録(そのまま支給も)、CSV でのまとめての登録、支給、返却の記録。
  種類ごとの在庫(未割当が何台あるか)と、返却期限超過など対応が必要な物品もホームで分かります
- **社員ごとに見渡せる** — 社員ページの名札ヘッダに「支給中」「返却待ち」の点数。
  新しい PC を渡しても、古い PC は実際に返ってくるまで「返却待ち」として残ります
- **台帳は表のまま、数千件でも使える** — サーバー側のページング・並べ替え・絞り込み。
  絞り込んだ一覧の URL をそのまま共有できます
- **二重に支給しない** — 同じ物品を同時に 2 人へ支給する操作は、データベースの段階で 1 件だけが成立します
- **既存の台帳を CSV で移せる** — UTF-8 と Shift_JIS(表計算ソフトの既定)の CSV を取り込む前に 1 行ずつ確認でき、
  支給先メールがメンバーに一致した行はそのまま支給します
- **記録が残る** — 登録・編集・支給・返却・利用停止・再開・訂正・取込をすべて履歴に残します。
  訂正しても元の値を履歴から辿れます
- **社員は Keelson のメンバーから選ぶ** — アプリ独自の社員台帳や社員登録はありません。
  退職などでメンバーから外れた人の記録も、そのときの名前で残ります
- **一般の社員は自分の分だけ** — 自分の支給品の確認と返却、空いている物品を自分に割り当てる操作ができます
- **AI アシスタントから話しかけて使える** — Claude や ChatGPT に「PC-0101 を山田さんに今日から支給して」
  「使っていない Windows のノート PC はある?」と頼むだけで、台帳を照会・記録できます(下の「AI アシスタントから使う」)

使っている様子は、テンプレート紹介ページの動画で確認できます。デプロイしたアプリは空の台帳から始まります
(種類と使用場所の初期値だけが入っています)。

## デプロイ

**secret の設定は不要です**。

### 導入手順

1. **社員一覧(Directory)を有効にします。** 支給先にワークスペースのメンバーを選ぶために必要です。
   ```bash
   keelson apps directory enable
   keelson deploy
   ```
   有効にしただけでは反映されません。再デプロイすると、アプリにメンバー一覧を読むためのトークンが渡されます
   (アプリのサーバー側だけで使い、ブラウザには渡しません)。メンバーのプロフィール画像もここから取ります
   (画像が無い人は頭文字で表示します)。詳しくは Keelson ドキュメントの
   [ログイン中のユーザー情報を使う](https://keelson.dev/ja/docs/building-apps/using-identity/) を参照してください
2. **管理者を決めます。** このアプリの管理者は、Keelson でアプリの `manage` 権限を持つ人です
   (既定では Owner / Admin / Developer)。物品の登録・代理支給・回収・訂正・CSV 取込・マスタ管理ができます。
   それ以外の人(`view` のみ)は「自分のページ」だけを使います。権限はコンソールの
   [グループとアプリ権限](https://keelson.dev/ja/docs/workspace/groups-and-app-access/) で変えられます
3. **マスタ管理** で物品の「種類」と「使用場所」(オフィス・在宅など)を自社に合わせて整えます
4. ホームの「物品を登録」で物品を登録します(「登録と同時に支給する」でそのまま社員に支給できます)。
   既存の台帳があれば「CSV で取り込む」でまとめて登録します(ひな形 CSV は取込画面からダウンロードできます)

### データベースの更新(migration)

デプロイのたびに、新しい版が動き始める前に `node scripts/migrate.mjs` が 1 回だけ実行され、
`migrations/` の未適用の SQL がデータベースに適用されます(`keelson.yaml` の `db.migrate`)。
失敗するとデプロイは失敗し、それまでの版が動き続けます。手元(ローカル)ではアプリの起動時に同じ処理が走ります。

### 任意の設定

| 変えたいこと                                        | 方法                                        |
| --------------------------------------------------- | ------------------------------------------- |
| 「今日」の基準になるタイムゾーン(既定 `Asia/Tokyo`) | `keelson.yaml` の `env:` に `APP_TIME_ZONE` |

## AI アシスタントから使う(MCP)

Claude や ChatGPT などの AI アシスタントをこのアプリにつなぐと、話しかけるだけで台帳の照会と記録ができます。
接続・ログイン・同意の画面は Keelson が用意します。アプリ側の権限の確認と履歴の記録は画面から操作したときと同じです。

接続先の URL は `https://<アプリの URL>/mcp` です。

- **Claude Code**: `claude mcp add --transport http equipment https://<アプリの URL>/mcp` を実行し、
  Claude Code で `/mcp` を開いて接続を承認します(Keelson の同意画面が開きます)
- **claude.ai / ChatGPT**: 設定からコネクタ(カスタムコネクタ)を追加し、上の URL を貼ります。Keelson の同意画面で承認します

接続の手順は、各 AI アシスタントと Keelson ドキュメントの更新で変わることがあります(暫定)。

言い回しの例:

- 「PC-0101 を山田さんに今日から支給して」
- 「使っていない Windows のノート PC はある?」
- 「鈴木さんが持っている物品は?」
- 「PC-0101 を返却したことにして」
- 「モニター EV2480 を 2 台登録して(管理番号 MN-0031 と MN-0032)」

- 物品の登録・他の人への支給・回収・利用停止と、台帳・他の社員の手持ちの照会は**管理者だけ**です。一般の社員は、
  自分の物品の確認・返却と、空いている物品を自分に割り当てることだけができます(画面と同じ)。
- 人は名前かメールアドレスで伝えます。同じ名前の人が複数いるときは、AI アシスタントが候補を示して確かめます。
  日付を言わなければ今日として記録します。
- 1 回の操作で扱う物品は 1 件です(2 台の登録は 2 回の操作になります)。
- AI アシスタント経由の変更も履歴に残ります。接続は、ワークスペースの管理者が Keelson のコンソールで失効させられます。

ツールの一覧と説明は `keelson.yaml` の `mcp:`、実装は `src/lib/server/mcp/` にあります
(足し方・変え方は [CUSTOMIZE.md](./CUSTOMIZE.md) の「AI 向けのツールを足す・変える」)。

## ローカル開発

```bash
pnpm install
pnpm dev
```

これだけで、画面・API・HMR・サンプルデータが 1 つの URL(既定 `http://localhost:5173`)でまとめて起動します。
ビルドや `.env` の作成は不要です。

`pnpm dev` は Keelson CLI(v0.6.11 以降)の `keelson dev serve` の後ろでアプリを動かします。`keelson dev serve` は
本番のゲートウェイと同じログイン情報(`X-Keelson-User-*` ヘッダ)を付けてリクエストを転送し、社員一覧(Directory)の
代わりも務めるローカル用の入口です。ログインする人と社員の一覧は、名簿ファイル
[`seed-data/dev-users.json`](./seed-data/dev-users.json) の人たちです(先頭の「(サンプル)山口」が管理者、ほかは一般の社員)。
詳しくは公開ドキュメントの [ローカルで動かす](https://keelson.dev/ja/docs/building-apps/local-development/) を参照してください。

- **利用者の切り替え**: `http://localhost:5173/__keelson/dev` を開いて名簿の人を選ぶと、その人として画面を表示します
  (再起動は不要)。一般の社員を選ぶと管理メニューは出ず、管理 API は 403 になります。「(サンプル)佐藤」は手持ちのある状態です。
- 最初から別の人で始めるときは `pnpm dev -- --as sample-sato` のように名簿の ID を渡します。
- CLI を入れていないときは `pnpm dev` が警告を出し、名簿の管理者 1 人として起動します(利用者は切り替えられません。
  社員の一覧は同じ名簿です)。CLI は `curl -fsSL https://keelson.dev/install.sh | sh` で入ります。

サンプルの台帳(物品・割当・履歴)は、ローカルのデータベースが空のときに `pnpm dev` が入れます
(空のまま始めたいときは `LOCAL_SAMPLE_DATA=0 pnpm dev`)。

`pnpm dev` は開発専用の入口です。デプロイと同じ動きの `pnpm start`(`pnpm build` のあと)は
プラットフォームのログイン情報が無いリクエストを 401 で拒否し、サンプルデータも入れません。

- データベースは libSQL。ローカルではファイル(`local.db`)を使うので、追加の設定なしで全機能が動きます。
- 添付ファイルはローカルでは `.keelson/files` に保存されます。
- ローカルには AI アシスタントの接続口(`/mcp`)はありませんが、ツールの本体は curl で直接呼べます:
  `curl -s -X POST localhost:5173/api/mcp/find_items -H 'content-type: application/json' -d '{"status":["unassigned"]}'`
  (一般の社員として試すときは `-H 'X-Keelson-Dev-As: sample-sato'` を足します)

品質チェック(フォーマット + lint + テスト + 文言規約)は 1 コマンドです:

```bash
pnpm check
```

ブラウザで基本操作を通して確かめる e2e テスト(Playwright)もあります。`pnpm check` には含まれません。
仕組みと書き方は [AGENTS.md](./AGENTS.md) の「e2e」にあります。

```bash
pnpm e2e:install   # 初回(と Playwright を上げたとき)だけ。テスト用の Chromium を入れる
pnpm e2e           # 一時的なデータベースで起動して確かめる(pnpm dev を起動したままでも動く)
```

e2e は一般の社員の操作も確かめるため、Keelson CLI(`keelson dev serve`)が必要です。CLI が無いときは、
入れ方を示すエラーを出してテストを始めずに終わります。

## 制限と注意点

導入前に次の前提を確認してください。多くは [PROMPTS.md](./PROMPTS.md) の改修例で調整できます。

- **管理者は全員分の台帳を見られます。** `manage` 権限を持つ人は、全社員の支給品・履歴・備考・添付を
  閲覧・操作できます。一般の社員は自分の支給品と、空いている物品の管理番号・物品名・種類・保管場所だけを
  見られます(他人の手持ちや備考を見る機能はありません)。
- **社員一覧(Directory)を有効にするまで、他の人へ支給できません。** 有効にしていない間や一覧を読めないときは、
  社員を選ぶ欄に「社員の一覧を取得できませんでした。」と表示されます(有効にする手順は上の導入手順 1)。
  アプリに社員を手で登録する機能はありません。
- **個数管理はしません。** 1 物品 = 1 行です。充電器やケーブルのように数で管理したいものには向きません。
- **CSV 取込は新しい物品の登録(と支給)だけです。** 既に登録されている管理番号の行は取り込みません
  (既存の物品の更新・返却の記録はできません。PROMPTS.md に更新を足す改修例があります)。社員は作りません。
  1 回 2,000 行・2 MB まで。
- **通知はしません。** 返却予定日を過ぎた割当は画面で「返却期限超過」と表示しますが、メールなどで
  知らせる機能はありません。
- **退職・異動の管理はしません。** 社員別一覧・社員ページから、必要な物品を回収(返却を記録)してください。
- **添付は 1 ファイル 10 MB まで・1 物品 20 件まで**、形式は PNG / JPEG / WebP / PDF です。
- **物品は削除できません。** 使わなくなった物品は「利用停止」にします(履歴を残すため)。
- **AI アシスタントの操作は、結果が分からないまま終わることがあります。** 応答が遅れて「結果不明」と表示されたときは、
  台帳で確かめてから頼み直してください(同じ管理番号の登録や、支給中の物品の支給は二重には記録されません)。
- **データベースの変更は `migrations/` の SQL ファイルだけで行います。** 適用済みのファイルを書き換えると、
  起動とデプロイが止まります(CUSTOMIZE.md「物品に項目を 1 つ足す」)。
